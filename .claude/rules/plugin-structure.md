# Plugin structure

Every plugin follows Anthropic's [standard layout](https://code.claude.com/docs/en/plugins/manifest-reference#standard-layout) (per component: [Add components to a plugin](https://code.claude.com/docs/en/plugins/components); every location below: [Explore the plugin directory](https://code.claude.com/docs/en/plugins/components#explore-the-plugin-directory)). What each plugin here ships is listed in the root `CLAUDE.md` › Per-plugin layout. What goes inside a skill folder is in [skill-structure.md](skill-structure.md).

## Layout

| Location                     | Holds                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `.claude-plugin/plugin.json` | The manifest. The only file in `.claude-plugin/`: components saved there don't load ([skills missing](https://code.claude.com/docs/en/plugins/troubleshooting#plugin-loads-but-its-skills-are-missing)). Claude Code loads a plugin without one; inside it, only `name` is required ([manifest file](https://code.claude.com/docs/en/plugins/manifest-reference#manifest-file), [fields](https://code.claude.com/docs/en/plugins/manifest-reference#fields)) |
| `skills/<name>/SKILL.md`     | Skills, one folder each. Claude loads one when a request matches its `description`; users run it as `/<plugin>:<name>` ([skills](https://code.claude.com/docs/en/plugins/components#skills))                                                                                                                                                                                                                                                                 |
| `commands/*.md`              | Legacy single-file commands. Write new ones as skills ([commands](https://code.claude.com/docs/en/plugins/components#commands))                                                                                                                                                                                                                                                                                                                              |
| `agents/*.md`                | Subagents, invoked as `@agent-<plugin>:<name>`. A subfolder becomes part of the name: `agents/review/x.md` loads as `<plugin>:review:x` ([agents](https://code.claude.com/docs/en/plugins/components#agents), [subfolders](https://code.claude.com/docs/en/plugins/components#organize-agents-in-subfolders))                                                                                                                                                |
| `hooks/hooks.json`           | Hooks, wrapped in a top-level `"hooks"` key. Each runs a shell command, HTTP request, MCP tool call, model prompt or subagent ([hooks](https://code.claude.com/docs/en/plugins/components#hooks))                                                                                                                                                                                                                                                            |
| `scripts/`                   | Files that hooks or skills run by path. A convention, not a folder Claude Code scans ([explore](https://code.claude.com/docs/en/plugins/components#explore-the-plugin-directory))                                                                                                                                                                                                                                                                            |
| `monitors/monitors.json`     | Background shell commands started with the session, or with `when`, on a named skill's first run, whose output reaches Claude as notifications ([monitors](https://code.claude.com/docs/en/plugins/components#monitors), [monitors field](https://code.claude.com/docs/en/plugins/manifest-reference#monitors))                                                                                                                                              |
| `output-styles/<name>.md`    | Output styles, listed in `/output-style` as `<plugin>:<name>` ([output styles](https://code.claude.com/docs/en/plugins/components#themes-and-output-styles))                                                                                                                                                                                                                                                                                                 |
| `themes/<slug>.json`         | Color themes, listed in `/theme` ([themes](https://code.claude.com/docs/en/plugins/components#themes-and-output-styles))                                                                                                                                                                                                                                                                                                                                     |
| `workflows/*.js`             | Workflow scripts. Each loads as `/<plugin>:<meta.name>`, a command users can also type ([distribute a workflow](https://code.claude.com/docs/en/workflows#distribute-a-workflow-in-a-plugin)). See [Workflows](#workflows)                                                                                                                                                                                                                                   |
| `bin/`                       | Executables. Put on the Bash tool's `PATH` while the plugin is enabled, and makes claude.ai and Cowork refuse to install the plugin ([executables](https://code.claude.com/docs/en/plugins/components#executables))                                                                                                                                                                                                                                          |
| `.mcp.json`                  | MCP servers, shown in `/mcp` as `plugin:<plugin>:<server>` ([MCP servers](https://code.claude.com/docs/en/plugins/components#mcp-servers))                                                                                                                                                                                                                                                                                                                   |
| `.lsp.json`                  | LSP servers: diagnostics and code navigation, mapped by file extension ([LSP servers](https://code.claude.com/docs/en/plugins/components#lsp-servers))                                                                                                                                                                                                                                                                                                       |

Put a prebuilt helper in a skill's `scripts/` and call it by its `${CLAUDE_SKILL_DIR}` path, which is the skill's own folder ([string substitutions](https://code.claude.com/docs/en/skills#available-string-substitutions)), not in a top-level `bin/`: claude.ai and Cowork don't install a plugin that has one ([executables](https://code.claude.com/docs/en/plugins/components#executables)).

Add only the folders a plugin uses; none is required ([add components](https://code.claude.com/docs/en/plugins/components#add-each-kind-of-component)). Don't put a `CLAUDE.md` at a plugin root: Claude Code doesn't load it, and `claude plugin validate` warns about it ([skills](https://code.claude.com/docs/en/plugins/components#skills)). Put instructions in a skill.

## Manifest

- `name` is the only required field ([fields](https://code.claude.com/docs/en/plugins/manifest-reference#fields)). Use kebab-case, and never start it with `claude-`, `anthropic-`, `anthropics-` or `cc-plugin-` ([name](https://code.claude.com/docs/en/plugins/manifest-reference#name)).
- Never change `name` after release ([rename or remove](https://code.claude.com/docs/en/plugins/publish#rename-or-remove-a-plugin)). It namespaces the plugin's components, and the marketplace entry name is the key users' `enabledPlugins` hold ([entry name and manifest name](https://code.claude.com/docs/en/plugins/loading#entry-name-and-manifest-name)); keep the two equal. To change the label users see, set `displayName` ([rename or remove](https://code.claude.com/docs/en/plugins/publish#rename-or-remove-a-plugin)). If a rename is unavoidable, add `"<old>": "<new>"` to a top-level `renames` map in `.claude-plugin/marketplace.json`, which rewrites the old key in `enabledPlugins` and `pluginConfigs`. Treat that map as append-only ([renames map](https://code.claude.com/docs/en/plugins/host-marketplace#migrate-users-with-a-renames-map)).
- Keep `version`, `description` and `author`; `claude plugin validate` warns when one is missing ([validate the manifest](https://code.claude.com/docs/en/plugins/manifest-reference#validate-the-manifest)).
- `version` follows [plugin-versioning.md](plugin-versioning.md). Set it only in `plugin.json`, never in the plugin's marketplace entry: if both set it, Claude Code uses the `plugin.json` value without a warning ([release a new version](https://code.claude.com/docs/en/plugins/host-marketplace#release-a-new-version)).
- A component path key starts with `./` ([path rules](https://code.claude.com/docs/en/plugins/manifest-reference#path-rules)) and must resolve inside the plugin ([containment](https://code.claude.com/docs/en/plugins/manifest-reference#containment-and-existence)). `commands`, `agents`, `outputStyles` and `workflows` replace the default folder scan, `skills` adds to it, and `hooks`, `mcpServers` and `lspServers` merge with the default file ([how each key combines](https://code.claude.com/docs/en/plugins/manifest-reference#how-each-key-combines-with-its-default-location)).

## Paths at runtime

- A marketplace install is copied into a per-version cache; only relative-path plugins in a marketplace added from a local path load in place. Files outside the plugin folder aren't copied, so reach plugin files only through `${CLAUDE_PLUGIN_ROOT}`, never `..` or a path into this repo ([in-place and copied plugins](https://code.claude.com/docs/en/plugins/loading#in-place-and-copied-plugins)). Symlinks to elsewhere in the marketplace are replaced by their targets, and symlinks pointing outside it are skipped ([symlinks](https://code.claude.com/docs/en/plugins/host-marketplace#share-files-within-a-marketplace-with-symlinks)).
- `${CLAUDE_PLUGIN_ROOT}` changes on every update, so don't write state there. Use `${CLAUDE_PLUGIN_DATA}`, which survives updates ([path variables](https://code.claude.com/docs/en/plugins/components#path-variables-and-persistent-data)).
- In a shell-form hook command, quote the variable so a path with spaces stays one word: `"\"${CLAUDE_PLUGIN_ROOT}\"/scripts/run.sh"` ([quoting](https://code.claude.com/docs/en/plugins/manifest-reference#quoting-and-path-separators)).
- Claude Code substitutes these variables in skill, command and agent bodies and exports them to hook, MCP and LSP processes ([path variables](https://code.claude.com/docs/en/plugins/components#path-variables-and-persistent-data)). They are not set in the Bash tool's environment, so write `${CLAUDE_PLUGIN_ROOT}` in the Markdown body, not as `$CLAUDE_PLUGIN_ROOT` in a command Claude composes ([where each variable resolves](https://code.claude.com/docs/en/plugins/manifest-reference#where-each-variable-resolves)).

## Workflows

A plugin ships Workflow scripts in `workflows/`, and Claude Code registers each as `/<plugin>:<meta.name>` ([distribute a workflow in a plugin](https://code.claude.com/docs/en/workflows#distribute-a-workflow-in-a-plugin)).

- A skill runs it by name: `Workflow({ name: "<plugin>:<meta.name>", args })`, with `args` as a real JSON value, not a JSON-encoded string ([Workflow tool](https://code.claude.com/docs/en/agent-sdk/typescript#workflow)). The approval prompt can offer "don't ask again" for a plugin workflow run by name ([approve the plan](https://code.claude.com/docs/en/workflows#approve-the-plan-before-it-runs)).
- Never pass the plugin's script as `scriptPath`: Workflow starts only a script the session can already read (the working directory, an `/add-dir` directory or a Read allow rule), and the plugin's install folder is none of these ([how a workflow runs](https://code.claude.com/docs/en/workflows#how-a-workflow-runs)).
- Users can type the bare command with no `args`, which leaves `args` `undefined` in the script ([pass input](https://code.claude.com/docs/en/workflows#pass-input-to-a-saved-workflow)). Guard every read with `args?.` and fail with a message that names the expected args.
- The script has no filesystem or shell access ([behavior and limits](https://code.claude.com/docs/en/workflows#behavior-and-limits)). A file it needs stays in the skill and reaches it as a `${CLAUDE_SKILL_DIR}` path in `args` for an agent to read, or is embedded in the script.

Observed in Claude Code, not in the docs:

- The script never passes through the skill's context when run by name.
- If the tool doesn't know the name (an older Claude Code build), the skill Reads `${CLAUDE_PLUGIN_ROOT}/workflows/<file>.js` and passes it verbatim as `script`.
- `meta.name` must not match a skill or command in the same plugin, since both would be `/<plugin>:<name>`.
- `meta.whenToUse` is appended to the workflow's entry in the skill listing. Set it to which skill invokes the workflow and the args it requires.

## Validate

`claude plugin validate --strict` treats warnings as errors and checks the manifest and every skill, agent and command frontmatter ([plugin validate](https://code.claude.com/docs/en/plugins/cli-reference#plugin-validate)), plus paths that are missing or escape the plugin ([validate the manifest](https://code.claude.com/docs/en/plugins/manifest-reference#validate-the-manifest)). A run on the marketplace doesn't open the skills, agents or commands of plugins in other directories, so validate each plugin directory too ([validate a directory](https://code.claude.com/docs/en/plugins/cli-reference#validate-a-directory)).
